# 手動アップデート確認とプレリリース選択の設計

日付: 2026-09-19
状態: レビュー用設計案。実装着手・リリースの承認を意味しない。

関連 Issue:

- [#878: macOS 自動アップデート](https://github.com/shinaoka/koushi-matrix/issues/878)
- [#931: メニューからの手動アップデート確認](https://github.com/shinaoka/koushi-matrix/issues/931)

## 目的と範囲

更新確認が実行されたか、その結果が何だったかをユーザーが判断できるようにする。メニューと設定に手動確認を設け、自動確認の設定に関係なく利用可能にする。あわせて、安定版のみを使うか、プレリリース版も更新対象に含めるかを選択可能にする。

初期のインストール対応範囲は #878 の macOS 配布版に合わせる。その他の OS や更新機能を利用できないビルドでは、非対応理由と公式リリースページへの導線を表示する。OS ごとの更新方式の新規実装は本設計に含めない。

この文書は目標とする動作を定義する。先行して作成された未確定の実装案が、この設計を満たしているとは扱わない。本作業は文書化のみとする。

## 手動確認の画面

メニューの「アップデートを確認…」と設定の同名ボタンは、同じ更新ダイアログを開く。結果が設定の別タブに隠れることはない。メニューからの確認は Matrix のログイン状態に依存させない。

| 状態 | 表示 | 操作 |
| --- | --- | --- |
| 確認中 | アップデートを確認しています… | 閉じる。重複確認は無効 |
| 更新なし | 現在のバージョンは最新です（vX.Y.Z） | OK |
| 更新あり | 現在のバージョン、更新先のバージョン、プレリリースであればその旨 | ダウンロード、あとで、リリース情報 |
| ダウンロード・検証中 | ダウンロード中／検証中 | 閉じる。重複ダウンロードは無効 |
| 準備完了 | 更新をインストールできます | 再起動してインストール、あとで |
| インストール中 | 更新を適用しています | 重複操作は無効 |
| 失敗 | 確認・ダウンロード・検証・インストールのどの段階で失敗したかと対処 | 再試行、閉じる。必要に応じて手動ダウンロード |
| 非対応 | この環境で更新機能を利用できない理由 | リリースページを開く、閉じる |

更新なしの「確認ボタン」は、結果を確認して閉じる **OK ボタン**とする。再確認ボタンへの置き換えではない。設定やメニューからは再度確認できる。

「最新です」は選択中の更新対象における結果であり、ダイアログには「安定版のみ」または「プレリリース版を含む」を併記する。現在のβ版より新しい安定版がない場合は「現在より新しい安定版はありません。安定版の公開を待つか、手動でインストールしてください」と表示し、安定版を使用中であるかのような説明を避ける。

ダイアログを閉じても確認・ダウンロードは継続する。再度開くと進行中の状態を表示する。ダウンロード完了だけではアプリを終了せず、「再起動してインストール」の明示操作で適用する。

日本語・英語の文言を用意し、キーボードで操作できるようにする。状態変化は支援技術にも通知し、閉じた後は起点へフォーカスを戻す。

## 設定と自動確認

| 設定 | 既定値 | 意味 |
| --- | --- | --- |
| アップデートを自動確認 | ON | 起動時と既存の定期確認タイミングで確認する |
| プレリリース版（β版など）を含める | OFF | 安定版に加えてプレリリース版も候補にする |

2項目は独立して永続化する。既存設定にプレリリース項目がなければ OFF として読み込む。手動確認で自動確認設定を書き換えない。

説明文は「開発中のバージョンも対象になります。不具合が含まれる可能性があります」など、選択の影響を示す。SemVer の解析仕様は通常の設定説明には出さない。

自動確認で更新がない場合はダイアログを開かない。更新がある場合は通知し、ダウンロードと再起動はユーザーが選ぶ。設定には現在のバージョン、選択中の対象、最終確認時刻と結果を表示する。失敗を「更新なし」に変換しない。

## バージョン規約と候補選択

バージョンは SemVer 2.0.0 とし、Git タグの表記は `v1.2.0-beta.1`、アプリ／更新情報内のバージョンは `1.2.0-beta.1` とする。

| 例 | 扱い |
| --- | --- |
| `1.2.0` | 安定版 |
| `1.2.0-beta.1`、`1.2.0-beta.2` | 通常のβ版の命名 |
| `1.2.0-alpha.1`、`1.2.0-rc.1` | プレリリース版として同じ設定の対象 |
| `1.2.0+build.123` | ビルドメタデータのみ。プレリリースとはしない |

プレリリース識別子が空でなければプレリリースと判定する。`beta` という文字列の部分一致や GitHub のフラグだけでは判定しない。公開時には SemVer の判定と GitHub の prerelease フラグの一致を検証する。

候補は対象 OS・アーキテクチャの更新資産がある公開済みリリースに限定し、SemVer の優先順位で比較する。draft、不正なバージョン、必要な更新情報の欠落は適格な候補にしない。不正なフィードは取得成功や更新なしとして扱わない。

- 設定 OFF: 現在より新しい安定版の最大バージョン。
- 設定 ON: 現在より新しい安定版とプレリリース版を合わせた最大バージョン。
- `1.2.0-beta.2 → 1.2.0` の正式版への更新を許可する。
- `beta.2 < beta.10` の数値順を守り、文字列の辞書順で比較しない。
- ビルドメタデータは優先順位に影響させない。同じ優先順位の再インストールは提案しない。
- 設定 OFF に戻しても自動ダウングレードしない。現在より新しい安定版が出たときに更新する。

## 配布情報

安定版とプレリリース版の最新候補を別のフィードとして公開する。設定 ON のクライアントは両方を取得し、候補を統合して比較する。β版フィードだけを見る方式では、後から出た正式版への更新を見逃すため採用しない。

フィードの URL は固定し、更新アーカイブの URL は公開済みのバージョン固定 Release を指す。安定版フィードは GitHub の `releases/latest` を使う。プレリリースを含める設定用には `latest-beta` の移動 Release を使うが、そこから取得するアーカイブは各バージョンの公開済み Release を指す。フィードにはバージョン、対象プラットフォーム、アーカイブ URL、署名を含める。

全資産の検証と Release 公開後にフィードを更新する。`latest-beta` は安定版公開時にも更新し、プレリリースがまだない場合でも安定版候補を返せるようにする。公開競合や古いジョブの遅延完了でフィードが古いバージョンへ戻らないよう、公開処理を直列化し、SemVer の比較で更新可否を判断する。

プレリリースがまだ存在しない状態は、明示的な「候補なし」として表現する。404 や通信失敗を候補なしと推測しない。設定 ON で片方の取得に失敗した場合は確認不完全として再試行を案内し、「最新です」と断定しない。

固定フィードの具体的な公開先と空候補の形式は、実装前の配布設計レビューで確定する。アップデータの複数 URL 設定が単なるフォールバックである場合、それを候補統合の代用にしない。

## 状態管理と競合

Rust 側の単一の更新管理主体が、確認・候補選択・ダウンロード・署名検証・適用を所有する。React は状態を表示し、型付きコマンドを送る。UI ごとにバージョン比較や更新処理を複製しない。

主な状態は未確認、確認中、更新なし、更新あり、ダウンロード中、準備完了、適用中、失敗、非対応とする。最終確認結果は進行中の状態とは別に保持する。

自動・手動の確認は同時に1件までとし、受付と確認中への遷移を不可分にする。自動確認中に手動確認された場合は同じ処理を共有し、その結果を手動ダイアログに表示する。確認中の要求を単に無視してユーザーに結果を返さない動作は避ける。

設定変更には世代番号を付ける。完了した確認結果は、開始時の世代が現在と一致する場合のみ採用する。旧設定の結果が後から到着しても新しい候補を上書きしない。

対象を切り替えたときは、選択済み候補・ダウンロード済み資産を再評価する。OFF にした後はプレリリース候補のダウンロード・適用を受け付けず、進行中のダウンロードが完了しても適用可能な状態にしない。ダウンロードと適用の受付時にも現在の設定と候補の適格性を確認する。

自動確認 OFF の場合、対象切替だけでは新しい通信を開始せず、既存候補を無効化して「更新対象を変更しました。確認してください」と表示する。自動確認 ON または手動確認が進行中なら、新しい対象で確認し直す。適用開始後の途中切替は許可しない。

## 失敗と観測

通信失敗、更新情報不正、署名検証失敗、書き込み権限不足は区別する。署名検証に失敗した資産は適用しない。再試行は失敗した段階に応じて行い、再起動は再度明示操作を必要とする。

診断には自動／手動の起点、対象設定、開始・終了時刻、現在／候補バージョン、結果、失敗段階を記録する。認証情報や個人情報は含めない。これにより「自動確認が実行されていない」と「実行されたが更新がなかった」を区別できる。

## 受け入れ条件

1. 自動確認 OFF でもメニューと設定から確認でき、設定値が変わらない。
2. 更新なしなら結果ダイアログに現在のバージョンと OK が表示され、OK で閉じる。
3. 自動確認の更新なしではダイアログを開かず、最終結果を設定で確認できる。
4. 更新ありでも、同意前にダウンロード・インストール・再起動しない。
5. 自動確認と手動確認の重複や連打で処理が並走せず、手動操作には結果が返る。
6. OFF でβ版を除外し、ON で安定版とβ版を比較できる。β版から正式版へ進める。
7. 数値識別子、ビルドメタデータ、同一バージョン、ダウングレードの境界を正しく扱う。
8. 確認中・ダウンロード中・準備完了時の設定変更で、古いプレリリース候補を適用しない。
9. 片方のフィードの失敗、不正データ、署名不一致を「最新です」に変換しない。
10. 非対応環境では理由と手動入手先が表示される。
11. 旧設定は自動確認の既存値を維持し、プレリリースは OFF で読み込める。
12. 日本語・英語、キーボード操作、結果通知が機能する。

実装時には候補選択と競合をヘッドレステストで検証し、画面テストで更新なしの OK と各操作を確認する。署名付き macOS 配布版の実機検証は別途必要であり、ユニットテストだけで実際の自動更新成功とは判定しない。
