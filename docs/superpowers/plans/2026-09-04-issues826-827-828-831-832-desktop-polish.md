# Issues #806, #826, #827, #828, #831, #832, #833 — desktop polish batch

## Scope and ownership

One PR delivers seven independently testable changes without inventing duplicate product state.

- #806 makes the existing Rust avatar owner the sole thumbnail-readiness source for message senders and read receipts, including cache hits and subsequent observations.
- #826 reuses the existing Rust-owned `SettingsPatch.locale` persistence and projected `LocaleDisplayProfile`; React only renders a selector and dispatches a complete locale patch.
- #827 reuses the existing Rust-owned `startDirectMessage(user_id)` command and stable timeline `sender` identity. React only turns a non-self sender avatar into an accessible button. Sender-name behavior from #730 remains profile-opening.
- #828 keeps normalization in Rust. It upgrades compatibility case folding and explicitly folds common dash/minus variants while preserving exact source-range reconstruction.
- #831 bounds the SDK historical-event fetch at the AccountActor ownership boundary, observes every frontend navigation result, and exposes a localized retryable failure instead of swallowing it. No retry loop or added product state.
- #832 uses Tauri's native About menu item/metadata where it provides cross-platform version display, avoiding duplicate frontend version plumbing and a custom modal.
- #833 keeps every visible normal-density sender name profile-clickable and preserves identical typography; compact hidden continuation headings remain absent from keyboard focus.

No Matrix protocol behavior changes. No snapshot schema change is expected. Reducer diagrams do not change.

## Upstream behavior and deliberate choices

Element-style timeline sender-name selection opens a profile; Koushi already shipped that in #730. #827 explicitly asks for direct messaging from the avatar, so the avatar becomes the direct-message affordance while the sender name continues opening Profile. Existing-DM reuse/new-DM creation remains the authoritative Rust `startDirectMessage` flow. Clicking the current user's avatar is inert/non-button.

Tauri's native About item is preferred over a custom React dialog because it obtains the packaged app version from native package metadata and avoids version drift. Metadata includes Koushi, version, copyright, dual license, and repository URL where supported by Tauri.
