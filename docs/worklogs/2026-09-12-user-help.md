# User help and AI navigation

## Scope

Add one English Markdown user guide under `docs/help/`, shared by people and
AI assistants. Route README and the documentation map to it; generate root
llms.txt from the guide's topic index. Add a dependency-free navigation check
and CI job. Include links to the exact release tag's help in future release
notes. Subsequent user requests expanded this PR to remove the question-mark
keyboard entry, add an AI-assistance Help dialog, reorganize user settings into
a foreground category dialog, document setting locations, and add a pre-PR
manual/code consistency checklist.

Consulted `AGENTS.md`, `REPOSITORY_RULES.md`, `docs/agents/verification.md`, and
the existing architecture ownership model. Work started from `origin/main`
commit `e0c6572d`; feature instructions were checked against that revision.

Reviewed the guide as a reader looking for sign-in, a direct message, missing
search results, and encryption recovery. Corrected labels and operation order
against the source (Accept invite, Edit, Send, file chooser before passphrase).
The DM dialog takes a full Matrix ID; the guide does not promise user search
there. Proposed chat export is explicitly not documented as a shipped action.
Existing trust-model help now links to the index and avoids prescribing a QR
flow without establishing that it is offered by the current app.

## Settings and Help follow-up

The user explicitly authorized the category/layout changes and requested that
manual/code consistency become part of the pre-PR checklist. Consulted the
local Element `UserSettingsDialog.tsx`: Account, Sessions, Appearance,
Notifications, Preferences, Keyboard, Security & Privacy, Encryption and
Help & About provide the relevant ordering. Koushi-specific local indexing
remains in Search history; no unsupported Element settings were added.

- Removed the top-bar question mark, account-menu keyboard entry, and native
  Help keyboard accelerator. Native Help now dispatches `showHelp`; the short
  dialog copies the public repository URL and gives ChatGPT/AI instructions.
  It also works while signed out; clipboard failure has a manual-copy fallback.
- User settings use the browser dialog top layer, with a category list and
  independently scrollable content. Language moved to Account, send behavior
  and shortcut reference to Keyboard, privacy toggles to Security & Privacy,
  and trust/recovery/key controls to Encryption. Existing setting values and
  commands remain Rust-owned. Category visibility and copy feedback are local
  presentation state; no protocol/schema changes were needed.
- A browser regression exposed local-reset confirmation behind the new modal.
  Reset/leave confirmations now use the same modal primitive; native modality,
  focus wrapping, Escape handling, and focus restoration keep them operable.
- Added `docs/help/settings.md` with the category/action map and updated task
  paths, including recovery under Encryption. Reviewed all existing setting
  controls against the table and English/Japanese catalogs. Removed an
  incorrect draft reference to a Shift+Enter send mode and matched native menu
  wording to `User Settings`.
- Added the checklist to `.github/pull_request_template.md`, repository rules,
  the existing pre-review verification instructions, and help maintenance.
  It covers paths, labels, prerequisites, outcomes and limits, with same-PR
  manual updates or an explanation. Mechanical links/index checks remain
  explicitly separate from semantic review.
